# Deployment Guide with Docker & Traefik

This guide explains how to deploy **Kichuu Lagbe** on a Linux server using **Docker Compose** and **Traefik**.

---

## 1. Prerequisites

1. **Docker & Docker Compose** installed on your server.
2. An active **Traefik reverse proxy** instance running in Docker on an external network (e.g., `traefik-net`, `proxy`, etc.).
3. A domain or subdomain (e.g., `kischuulagbe.ovijit.com`) pointing to your server's public IP address (A record).

---

## 2. Quick Start Deployment

### Step 1: Upload or Clone the Code to your Server
```bash
git clone <your-repo-url> /opt/kichuu-lagbe
cd /opt/kichuu-lagbe
```

### Step 2: Create your Production `.env`
```bash
cp .env.example .env
nano .env
```

Set the following variables in `.env`:
```env
# Your actual domain pointing to the server
DOMAIN=kischuulagbe.ovijit.com

# The name of the Docker network your Traefik container is attached to
# (From your server: `traefik-public`)
TRAEFIK_NETWORK=traefik-public

# The name of your Traefik ACME certresolver (usually `letsencrypt` or `myresolver`)
TRAEFIK_CERTRESOLVER=letsencrypt

# A secure random secret for JWT auth tokens
JWT_SECRET=kichuu-lagbe-production-jwt-secret-9b2f6c8d1e3a4570

# Database: MongoDB Atlas (configured) or local container (mongodb://mongo:27017/kichuu_lagbe)
MONGODB_URI=mongodb+srv://contactsequenceit_db_user:2CTQddiTsHG9rfO6@kldb.bdglrdv.mongodb.net/kichuu_lagbe?retryWrites=true&w=majority
```

> **Note on Traefik Network**: If your Traefik network is called something else (e.g. `proxy` or `web`), simply set `TRAEFIK_NETWORK=proxy` in `.env`. If the network does not exist yet, you can create it with:
> ```bash
> docker network create traefik-net
> ```

---

### Step 3: Build and Start Containers
```bash
docker compose up -d --build
```

Docker Compose will:
1. Build the frontend **Vite** bundle in a multi-stage Alpine build and serve it using optimized **Nginx** on port 80.
2. Build the backend **Express** server on Node 20 Alpine on port 5000.
3. Start local **MongoDB 7** on the isolated internal network.
4. Attach `web` and `api` to your Traefik network with routing and automatic TLS certificates.

---

### Step 4: Run Initial Seed Data (Optional)
To populate the database with default accounts (Resident, Shop Owner, Service Provider, Rider, Admin, sample shops, and product catalog):

```bash
docker compose exec api npm run seed
```

Default credentials generated by seed:
- **Resident**: `tanvir@kichuulagbe.local` / `Resident123!`
- **Shop Owner**: `shop@kichuulagbe.local` / `Shop12345!`
- **Service Provider**: `kabir@kichuulagbe.local` / `Provider123!`
- **Rider**: `hasan@kichuulagbe.local` / `Rider1234!`
- **Admin**: `admin@kichuulagbe.local` / `Admin1234!`

*(You can change these passwords in `.env` before running the seed).*

## 3. Architecture & Routing

```
[ Internet ]
     │
     ▼
[ Traefik (Ports 80 / 443 with Let's Encrypt TLS) ]
     │
     ├─── Host: `${DOMAIN}` && Path: `/api/*` ──────► [ api:5000 (Express Node.js) ]
     │                                                               │
     │                                                               ▼
     │                                                    [ mongo:27017 (MongoDB) ]
     │
     └─── Host: `${DOMAIN}` ────────────────────────► [ web:80 (Nginx SPA) ]
```

- **Zero CORS issues**: Both the React frontend and API are served under the same origin (`https://${DOMAIN}`).
- **SPA Routing**: Nginx automatically rewrites non-file routes (`/app`, `/merchant`, `/provider`, etc.) to `/index.html`.
- **Uploads up to 15MB**: Nginx and Express are configured with a 15MB limit to allow high-res shop cover banners, store logos, and product photos.
- **Security Isolation**: MongoDB is only accessible on the internal bridge network and never exposed to the public internet.

## 4. Useful Operations & Commands

### Check Service Status
```bash
docker compose ps
```

### View Live Logs
```bash
# View all logs
docker compose logs -f

# View backend API logs
docker compose logs -f api

# View frontend web logs
docker compose logs -f web
```

### Restart Services
```bash
docker compose restart
```

### Stop Services
```bash
docker compose down
```
*(Data in MongoDB is preserved inside the `mongo_data` volume).*
